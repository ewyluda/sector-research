# UX Discovery Audit — sector-research

Session B1 of `2026-06-10-improvement-campaign.md`. Walked every surface live (backend on `127.0.0.1:8000`, frontend dev on `:3000`, real DB data) with Playwright on 2026-06-10. Screenshots in `docs/superpowers/ux-audit-2026-06-10/` (numbered, referenced inline below). No code changes were made; two bugs were verified in source to confirm root cause.

**Note:** executed before A1 (no CI exists yet) at user direction — B1 itself is read-only, so the missing CI gate doesn't affect this session, only B3.

## 1. Per-surface friction log

### Today `/` (01-today.png)
Works well as a triage screen: banner, 4-day calendar slice, needs-attention list. Friction:

- **Catalyst event cards render their title twice.** Verified in `components/catalysts/EventCard.tsx`: for `kind === "catalyst"` the title row prints `event.title` and the subtitle row prints `event.title` again. Long catalyst sentences appear back-to-back, doubling card height in calendar lanes (visible in 01-today.png, Thursday lane). **S fix.**
- **Question-rollup links aren't deep-linked.** "CORZ — 86 open P1 questions" links to bare `/questions`, but `/questions?ticker=CORZ` works and is exactly where the user is headed. One-line fix. **S.**
- Near-duplicate 8-K events both surface (two APLD cards for the same $1.59B notes offering, one from issuer PR, one from announcement). No dedup/grouping by ticker+topic. **M** (dedup heuristic) — also visible on the status drawer.
- Attention list mixes two item types (material events, question rollups) with identical visual weight; no severity ordering across types.

### Themes `/themes`, `/theme/[id]`, `/theme/new` (02, 03, 14)
Grid and creation form are fine. Theme detail (the discovery surface) has the most dead ends:

- **"Signal data stale — last updated >36h ago" banner with no refresh affordance.** `POST /api/themes/{id}/signals/refresh` exists but isn't wired to any button on this page. The user can see staleness but can't act. **S.**
- **No path from a company card to `/company/[ticker]`.** The detail pane's only action is "Run Quick Screen →". To look at a company you just discovered you must retype the ticker in the nav box. **S** (add a link).
- "X Signal" heading renders as "X SignalT2" — the tier badge concatenates with no spacing. **S.**
- No indication on cards that a ticker already has a completed run/thesis (a "Researched" filter exists, but cards don't show which run or link to it).

### Status `/status` (04, 05, 06, 07, 32)
The strongest fleet surface. Drawers (material events, earnings) expand inline and deep links (`?expand_events=`, `?expand_earnings=`) auto-open correctly.

- **`↻ Workspace` is disabled on 8 of 12 rows with no visible reason.** The preflight reasons (`no_ticker_model`, `unsaved_model_draft`, …) exist and are put in a native `title` tooltip only. The dominant reason in practice is `no_ticker_model` — see Journeys §3. **S** (visible reason / affordance), **M** (rethink the model prerequisite, see §3 Earnings day).
- Catalyst text and the countdown chip concatenate in the accessibility tree ("…re-rating.1d"); visually OK but text run-on in some widths.
- Row menu (⋯) has only "Open report" / "Archive" — no "Company workspace", no "Model", no "View questions". The row is the natural hub for a ticker; everything except the report requires the nav ticker box. **S.**
- Kill-criteria summary is in the board payload but there's no kill-criteria drawer/toggle on the board itself; armed/triggered state is only visible inside a workspace-run report. (CLAUDE.md advertises kill-criteria toggles as a status-board feature.)

### Catalysts `/catalysts` (08)
Calendar + agenda is good. Two notes:

- Fuzzy-dated catalysts ("Next 1-3 mo") dominate the 30/90-day agenda as a wall of long sentences — they swamp the precisely-dated items. Could be collapsed into a per-ticker group or shown as compact rows.
- NVDA and PL catalysts appear here, but neither ticker has a status-board row (their runs are archived or superseded). Calendar universe ≠ board universe is intentional but unmarked; an "archived thesis" tag on those agenda rows would prevent "why isn't this on my board?" confusion.

### Questions `/questions` (09, 10)
Rollup → drill-down (`?ticker=`) works. Friction:

- **311 open questions across 6 tickers with only per-row actions.** No bulk dismiss/resolve, no priority filter in the drilled view, no "dismiss all P3". At CORZ's 112 questions, the page is unusable as a workflow — it's a graveyard. **M** (bulk actions + filters).
- Today's attention list double-counts this backlog (6 of 11 attention items are question rollups every single day) — staleness with no decay or snooze.

### Library `/library` (11)
**The weakest surface.** A flat chronological list of ~60 giant cards:

- Same ticker appears up to 7 times (ORCL); no grouping by ticker or "latest per ticker" view; finding a specific past run = scroll + squint.
- **Zombie runs:** several April runs stuck in "Running / pending" and old "Waiting for your approval" gate-flow cards that can no longer be acted on (the gate flow was removed). They clutter the list and look actionable. No delete/abandon action exists. **M** (backend cleanup action + UI affordance, or auto-expire).
- Status chips (Complete/Awaiting/Running/Watchlist/Gate-Gaps) reflect the old flow vocabulary.

### Performance `/performance` (12, 13)
- **Default view is a wall of em-dashes.** Defaults to 3m offset; almost no outcome has 3m data yet (oldest runs are ~2 months old), so the hero band, by-verdict and by-theme tables all render "—" despite N=19. Should default to the latest offset with data, or annotate "no 3m snapshots yet". **S.**
- "By verdict" mixes run statuses (`completed`, `watchlist`) with workspace verdicts (`healthy`, `imminent`) in one Band column — taxonomically confusing.
- Superseded outcome rows are interleaved with open ones (CORZ row appears 3×, +18.24% each); default should hide superseded or group by run lineage.
- Trade journal section + modal form are clean; `?log_trade=` deep links work from status board and company header.

### Pipeline `/pipeline/new`, `/pipeline/[runId]` (15, 16, 17, 18, 19)
The report page is the most polished surface in the app (sticky section nav, ⌘K section jump, print view, citations index, footer actions).

- `/pipeline/new` copy says "Runs 4 due-diligence phases automatically, then waits for approval before sizing" while listing 5 phases — stale copy from the gate era. **S.**
- ⌘K palette is report-scoped only. There is no **global** command palette / quick-switcher anywhere; the nav ticker box (which works, incl. lowercase) is the only fast-nav tool. Given this is a keyboard-first single-user tool, a global ⌘K (tickers, surfaces, runs) is the highest-leverage nav addition. **M.**
- Report header has "Refresh workspace →" and a model badge, but no link to `/company/[ticker]` (the company hub). **S.**

### Workspace `/workspace`, `/workspace/[runId]` (20, 21)
- **`/workspace` is a 4-row history table with no kick-off affordance and no link to anything except run reports.** As a top-level nav entry it's nearly content-free; kick-off lives only on the status board and report header. Either give it the fleet/kick-off framing or demote it from the nav. **IA decision.**
- Failed runs (ORCL, May 9) show "Failed" with no retry/diagnose affordance.
- **The run report renders in the light theme while the nav and the rest of the app are dark** — the most jarring visual break in the app (see §4).
- Step cards are good (kill criteria with armed status, catalyst windows, sensitivity grids). "5. Differentiation — No peer comp data available" and "2. Research — no new filing text" render as flat text; fine.

### Prospectus `/prospectus` (22)
- **Empty surface occupying a top-level nav slot.** Zero reports; the empty state says "Create one from the Filings page" — i.e., even its creation entry point lives elsewhere ("+ New prospectus report" button on `/filings`). Strong candidate for demotion to a contextual entry (e.g., from Filings) or an overflow menu. **IA decision.**

### Filings `/filings`, `/filings/graph` (23, 24, 25)
The chores hub. Theme-grouped cards with per-ticker Fan out / Ingest latest / Extract competition and per-theme bulk "Fan out N" — bulk affordances are good.

- **Counterparty resolution queue: 50 pending and no way to say "none of these".** For private companies (OpenAI, "ENTRA1", Google) every fuzzy candidate is garbage (OpenAI's best matches: PENTAIR plc, Opera Ltd, OPENLANE…). The only actions are "Use this" per candidate. Queue can never reach zero; resolution work is futile for the most common case. Needs a "dismiss / not public / mark private" tombstone action (likely a small backend addition). **M — top-3 finding.**
- 13 tickers across two themes sit at "no sections yet — Ready to ingest"; nothing surfaces this as a to-do anywhere else in the app (no badge on the nav entry, no Today item).
- Wording inconsistency: "Extract competition" vs "Re-extract competition" (same action, different state); "Fan out" does ingest+extract+resolve but the three separate buttons are also exposed with no explanation of overlap.
- `/filings/graph` is a nested disclosure list (not a visual graph). Defaults to 1-hop even though its purpose and its inbound link ("Explore 2-hop graph →") are the 2-hop view. ORCL shows 2 counterparties — sparse data makes the page feel broken even when it's working.

### Company `/company/[ticker]` + tabs (28, 29, 30)
The best surface in the app alongside the report page: header with live quote + Log trade + lens select; Overview (chart, stats grid, Bulls/Bears with section citations); Theses tab tracks board state + run history per ticker.

- **Peers tab renders fully light-themed (including the nav)**, Overview/Theses render dark — route-level theme split inside one surface. (Compare `/compare`, which uses the same PeerCompTable, renders dark.) See §4.
- **StatisticsGrid scaling bugs:** ORCL "Gross 118.1%" (true: ~71%), "FCF −5911.7%", "Rev 5Y CAGR 70.3%" — percent-vs-fraction and unit mix-ups from raw FMP `ratios-ttm` keys. Same 118.1% shows in `/compare` margins column, so it's in the shared comp builder path. Data-quality bug, not UX, but it destroys trust on the flagship surface. **S/M fix, Track A/C territory.**
- Theses tab surfaces the same zombie "PENDING" April runs as Library.
- `/company/[ticker]` is reachable only via the nav ticker box and earnings/journal deep links — not from theme cards, status rows, or report headers, all of which are natural origins. (Same gap noted per-surface above.)

### Compare `/compare` (31)
Works; URL-as-state with add/remove chips; dark theme. Only entry points are the company Peers tab ("Open in compare →") and hand-typed URLs — fine by design.

### Model `/model/[ticker]` (26, 27)
- **Intra-page theme split:** Forecast tab content renders light; Reverse DCF tab renders dark. Both under a dark nav. See §4.
- Reverse DCF: "Implied IRR —" renders as a bare em-dash with no explanation when the solver fails/has no solution at the live price. The thesis-vs-priced-in table also has unexplained "—" cells. **S** (annotate).
- Forecast grid drivers show large runs of "—" cells (drivers without values); visually hard to tell "not applicable" from "missing".

## 2. IA critique

**Current nav (12 items):** Today · Themes · Filings · Catalysts · Status · Prospectus · Workspace · Questions · Library · Performance · +New Run · [Ticker box]. It's over-full, and prominence doesn't match usage:

| Nav entry | Observed content | Verdict |
|---|---|---|
| Today | rich, daily | keep (home) |
| Status | rich, daily | keep — arguably the real hub |
| Themes | rich, weekly | keep |
| Catalysts | rich | keep (or merge into Today as a tab — it already shares EventCard) |
| Filings | chores hub | keep, but it's a workflow page, not a reading page |
| Performance | rich | keep |
| **Prospectus** | **empty; creation lives on /filings** | demote to contextual entry from Filings |
| **Workspace** | **4-row history, no kick-off** | demote (history could live under Status or Library) |
| **Questions** | rollup + list | could fold into Status (per-ticker) + Today (triage); standalone page adds a hop |
| **Library** | flat archive with zombies | keep but rebuild as grouped-by-ticker archive; or merge with run history under each company |
| +New Run | form | could fold into a global ⌘K / Today action |

**The company workspace (`/company/[ticker]`) is the app's natural hub and has no inbound links from the surfaces where you think about a company** (theme card, status row, report header). The nav ticker box is the only general entry. Either nav-level "recent companies" or, better, ticker-everywhere linking: every ticker string in status/theme/report surfaces should link to `/company/[ticker]`.

**No global quick-switcher.** ⌘K exists only inside reports for section jump. A global ⌘K over (tickers, surfaces, recent runs, actions like "log trade", "new run") would collapse most of the nav-fullness problem for a keyboard-first expert user and make demotions painless.

## 3. Journey maps

**Morning check** (open app → triage → act): ~3 steps for events (Today → attention item → status drawer auto-open ✓). Questions path is +2 clicks because rollup links drop the ticker filter. Acting on a stale thesis from Today is blocked by the disabled-workspace problem below. Overall: good, the deep links work; the friction is what's *in* the list (duplicate events, never-shrinking question counts), not the route.

**New idea** (discover → research → model): Themes → theme → card → "Run Quick Screen →" (prefilled) → Begin → live report. Clean, ~5 clicks to a running pipeline. Gaps: no way to inspect the company (`/company/`) before committing to a run without retyping the ticker; stale signals can't be refreshed from the UI.

**Earnings day** (calendar → drawer → refresh thesis → updated verdict): Calendar/Today → earnings chip → `?expand_earnings=` drawer (date, estimates, pre-earnings brief button) ✓. Then "↻ Workspace" — **disabled for most tickers because workspace refresh hard-requires a saved `/model/[ticker]` (preflight `no_ticker_model`)**. The recovery path is invisible: open report → notice model badge → `/model/[ticker]` → Initialize (LLM call, ~minutes) → Save version → back → ↻. That's a 6-step hidden detour the UI never explains. Either surface "Create model first →" on the disabled button, or make the model prerequisite optional for refresh. **Top-3 finding.**

**Filings chores** (ingest → extract → curate → graph): Bulk "Fan out N" per theme is the right shape (3s polling progress works). The chore *backlog* is invisible outside the page itself, and the curation queue is a dead end for private counterparties (no dismiss). Graph exploration from a report's supply-chain card works but lands on 1-hop default.

## 4. Visual consistency

The app is split between **two theme systems**:

- **CSS-variable light theme** (the stated target direction per the campaign doc): workspace run report, model Forecast/History tabs, company Peers tab — these render light, and on `/company/[ticker]/peers` even the nav renders light.
- **Hardcoded dark Tailwind palette** (`bg-slate-900`-style classes): everything else (~15 surfaces).

Result: navigating Status (dark) → workspace report (light) → back, or switching tabs inside `/model/[ticker]` (Forecast light, Reverse DCF dark) produces full-screen theme flashes. **This is the single biggest visual-consistency decision for B2: pick one theme, migrate the rest.** Everything else (score colors via `scoreColors.ts`, section registry, print attributes) appears consistently applied. Minor: monospace ticker styling is consistent; chip/badge vocabularies differ slightly between status board (⟿, 8-K, 📅 chips) and Today (text rows).

Data-trust issues that read as visual bugs: FMP ratio scaling (Gross 118.1%, FCF −5911.7%) on company overview + compare; em-dash walls on Performance and Reverse DCF with no "why".
